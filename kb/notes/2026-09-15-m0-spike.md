# M0 记录：工具链 + gpui-kit spike

PRD 里程碑 M0 完成。本文记录环境准备的实际步骤、构建耗时、spike 验证结果与对后续里程碑有影响的发现。

## 环境

| 项 | 结果 |
|---|---|
| Rust | `mise use rust@1.98.1`（写入 `mise.toml`；mise 底层调 rustup，toolchain 装到 `~/.rustup`，`~/.cargo/bin` 已在 PATH 且优先于 Homebrew 的 rust 1.91） |
| Metal Toolchain | `xcodebuild -downloadComponent MetalToolchain`，688MB，约 2 分钟；装完 `xcrun -sdk macosx metal --version` 可用，未启用 `runtime_shaders` |
| 依赖锁定 | `gpui-kit = "=0.6.1"` → 解析到 `gpui-pre 0.3.5`、`gpui-base / gpui-component / gpui-kit-assets 0.6.1`，`Cargo.lock` 已提交 |
| cargo target | 全局 `~/.cargo/config.toml` 把所有项目的 target 指到 `~/Library/Caches/cargo-target`，仓库里没有 `target/`；二进制在 `~/Library/Caches/cargo-target/debug/agent-session-manager` |

## Spike 内容（`crates/app/src/main.rs`）

- `DataTable` + `TableState<SessionTableDelegate>`：10,000 条假 session，11 列，Preview 列 48px 两行布局（标题 + 灰色预览），`perform_sort` 对索引向量原地排序，同值按 updated 降序稳定
- `h_resizable("main")` 双面板：表格 960px 初始宽 + 详情面板，`cmd-\` 折叠
- `TabBar::segmented`（搜索范围 / 展示模式）、`DatePickerState::range` + `DateRangePreset`、`StatusBar`
- `ASM_SPIKE_AUTOPLAY=1`：启动 3s 后 `scroll_to_row(5000)` + 选中，再 3s 后按 Prompts 降序；用于免 GUI 自动化截图

实测数字：生成 10k 行 37ms，`TableState::new` 后 43ms；10k 行排序 6.6–8ms（debug 构建，主线程直接做完全够用）。

截图归档：`tmp/2026-09-15-m0-spike/`（`1-initial.png` 初始、`2-scrolled.png` 滚到第 5000 行并选中、`3-sorted.png` 按 Prompts 排序）。窗口级截图用同目录下 `winid.swift`（按进程名取 `CGWindowID`，再 `screencapture -l`），比全屏截图干净。

## 与调研文档的差异 / 补充

- `date_picker` 与 `calendar` 在 `gpui_kit::component::date_picker` / `::calendar`（`time` 模块私有，通过 `pub use time::{calendar, date_picker}` 暴露）
- `h_resizable` / `resizable_panel` / `ResizableState` 在 `gpui_kit::component` 根，也有 `component::resizable::*` 兼容路径；`h_resizable(id)` 只接 id，状态可选 `.with_state(&Entity<ResizableState>)`
- `TabBar::on_click` 的回调签名是 `Fn(&usize, &mut Window, &mut App)`，可直接传 `cx.listener(..)`
- `StatusBar::new().left(..).right(..)`，`child()` 进中间区域
- `TableState::perform_sort` 私有；程序化排序只能调 `delegate_mut().perform_sort(..)`，表头箭头不会跟着变（M2 需要时用 `Column::sort(..)` 重建列后 `refresh(cx)`）
- 表格横向也虚拟化：panel 比列总宽窄时出现横向滚动，Size 之后的列被裁掉。M2 要么让 Preview 列自适应，要么按窗口宽度算列宽
- `gpui_kit::actions!` 是 kit 自己的宏，`#[derive(Action)]` 走 `gpui_kit::Action`，不用 `gpui::` 路径
- 启动时 stderr 有一条 `error messaging the mach port for IMKCFRunLoopWakeUpReliable`，是 macOS 输入法框架的噪音，无影响
- 第一次 `cargo check` 要 37s（为全部依赖生成 metadata），之后才快；rust-analyzer 首次打开同理

## 对后续里程碑的结论

- 方案 A（gpui-kit 0.6.1）成立，没有遇到需要换路的阻塞
- M1 可以直接开始：`crates/core` 已建好空壳，无 gpui 依赖
- M2 的表格骨架可以直接从 spike 的 delegate 演化：把 `rows: Vec<Arc<SessionRow>>` 换成 core 的真实类型，`ix` 改为 filter → sort 的产物
