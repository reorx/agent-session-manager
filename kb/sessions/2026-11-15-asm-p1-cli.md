## 自己的决定

1. 默认值：`search` `-n 20`、`--snippets 3`、`--sort recent`；`projects` `-n 50`、默认不限时间。片段为首个命中前 60 字符、起点后 140 字符；`title:` 最多 120 字符，`prompt:` 160 字符且只在会话有自己的标题时出现；`session` 卡片的 prompt 300 字符、工具最多列 8 个、文件 10 个；JSON 里的 prompt 截到 2,000 字符；前缀歧义时 stderr 最多列 20 个候选（JSON 给全部）。
2. 时间范围：会话的活动区间（首条 prompt 到最后更新）与范围重叠就算在内，而不是只看 `updated_at`，所以 `--until` 会包含跨过截止日的会话。和 `asm cost --since/--until`（只看更新时间）口径不同，这是有意的：PRD 写的是「范围内有过活动的会话」。`--days` 可带小数，`--days 0` 不限；`--until` 可单用；`--days` 与 `--since` / `--until` 互斥（exit 2）。
3. `--project`：含 `/` 或以 `~` 开头才当目录、精确选中该项目，否则对项目路径或编码目录名做不分大小写的子串匹配。不学 `list`「存在的目录就当路径」，避免当前目录下恰好有同名子目录的意外（M1 笔记记过这个坑）。
4. 排除当前会话也用于 `projects`（计数和最近活动），`--include-self` 恢复；`session ID`、`transcript ID` 不排除。
5. 新命令都有 `--no-scan`；JSON 的 `meta.index_refresh` 为 `done` / `busy` / `skipped`。
6. JSON：pretty print；时间用带本地偏移的 RFC 3339；失败（exit 1）时 stdout 给 `{"error": {"code", "message"}}`，`code` 为 `not_found` / `ambiguous`（带 `candidates`）/ `failed`。`search` 结果另加 `term_hits`（每个概念命中多少项），片段加 `terms`（这段命中了哪些概念）和 `offset`（所在 JSONL 行的字节偏移）。
7. `search` 文字输出的第二行写 `N turns` 而不是 prompt 数，好和片段的回合号对上；`session` 卡片两个都给（`turns: 21 (23 prompts)`，后者是表格 Prompts 列的口径）。
8. 片段挑选：命中概念多的优先，再按类别 `prompt > reply > thinking > tool-input > tool-output > other`，再按位置；先保证每个概念至少出现一次。工具类别排在 `other` 前（Tech Design 只排了索引里的四类）。
9. `--tool` 按工具名精确匹配、不分大小写，只限制工具类别；`--in` 没写工具类别时自动加上 `tool`。
10. transcript 阅读模式（用了 `--turns` / `--grep` / `--thinking` / `--tools` 任一）：除 spec 写的以外，还输出所有 agent 文字（含工具调用之间的说明，每段一个 `<agent>`）和 `other` 文本（`<other>`）。不这样的话，`asm search` 在 reply（含过程说明）和 `other` 里报的命中，用 `--turns N` 读不到，核实这一步就断了。工具输入和 `<other>` 也按 2,000 字符截断（spec 只说了输出）；不带 `--tools` 时 `<turn-summary>` 紧跟 `<user>`；`--grep` 按 Tech Design 是任一 TERM 命中就保留；加了 `--regex`（Tech Design 的 `Query` 有 regex 字段）；`--turns` 超出范围 exit 1；开标签带 `turns=` 和 `matched=`；`--outline` 是纯文本，每回合一行。
11. `--no-color` 总是胜过 `--color`，不论位置。原想做成「最后一个生效」的别名，但 clap 的 `overrides_with` 管不到一个写在子命令前、一个写在子命令后的全局参数（`--no-color list alpha --color always` 仍然无色），所以改成固定优先级并写进 cli.md。
12. 一致性测试比 Tech Design 写的严：每个参数要在所在小节参数表里有自己的一行（出现在第一格），不只是「小节里出现」。原因见下文「反向检查」：删掉 `--rebuild` 那一行后，旧写法仍然通过，因为正文里还有 `asm index --rebuild`。位置参数按 value name（`ID`、`TERM`）检查，短参数（`-n`）也检查；代码块里的 `# 注释` 不算标题。
13. 写锁：CLI 的读写连接把 busy timeout 设为 2 秒（rusqlite 默认 5 秒）；`asm index` 拿不到锁仍报错退出 1（它就是来写索引的）；`favorite` / `unfavorite` / `favorites-dir` 操作完的那次重扫也走回退（操作本身已经成功，不该因为重扫被挡而报错）。提示行就是 spec 里那句 `index busy, results may miss the last few minutes`。

### R1-1：同时建库

1. `use_wal`：WAL 切换失败且是 busy 时，每 5 ms 重试一次，最多等 busy timeout，然后照常报错。切 WAL 不能放进事务。

3. `open_with` 只在 `is_corrupt`（`NotADatabase` / `DatabaseCorrupt`）时删库重建。其他错误（busy、磁盘满、权限）原样返回，不动文件。`schema_version_mismatch_and_corrupt_files_trigger_a_rebuild`（写入非 SQLite 内容）仍然通过。
