# 发布 1.0 与应用内自动更新

## 结果

- v1.0.0 已发布：https://github.com/reorx/agent-session-manager/releases/tag/v1.0.0（`AgentSessionManager-1.0.0.dmg`、`SHA256SUMS`、`appcast.xml`），`reorx/homebrew-tap` 有 `agent-session-manager 1.0.0`（bot 提交 `c0d00a9`）
- 发布流程、组成、密钥、验收方法都在 `kb/docs/release.md`，本文只记这次的决定、经过和证据

## 决定

| 问题 | 结论 | 谁定的 |
|---|---|---|
| Release 放哪 | 本仓库，仓库改为公开（Sparkle 需要匿名下载 feed 和 dmg） | 用户 |
| 架构 | 只出 Apple Silicon | 用户 |
| Homebrew cask | 要，推 `reorx/homebrew-tap` | 用户 |
| 更新框架 | Sparkle 2.10.0，运行时用 `NSBundle` 加载 bundle 里的 framework，`objc2` 调 `SPUStandardUpdaterController`，不链接 | 我（与用户其他 app 一致；debug 二进制不受影响） |
| 打包方式 | 自写 `bundle-app.sh`，不用 cargo-bundle | 我（Info.plist 要写 Sparkle 键和 tag 版本，脚本更直接） |
| 数据目录 | 保持 `dev.reorx.AgentSessionManager`，不随 bundle id 迁移，原 known issue 删除 | 我 |
| dmg 文件名 | `AgentSessionManager-<v>.dmg`，GitHub 会把资源名里的空格换成点 | 我 |
| 最低系统 | macOS 14（`LSMinimumSystemVersion`、cask `:sonoma`）；二进制本身未设部署目标，没在更低版本上试过 | 我 |
| 版本号 | 只来自 tag，构建号是 run number；Cargo.toml 的 version 不动 | 沿用 skill |

## 经过与证据（`tmp/2026-10-28-release/`）

1. 公开前扫描：gitleaks 扫全部 47 个提交，无密钥；自写脚本扫所有历史 blob 的邮箱、IP、他人路径、URL，只有本机项目名、本地路径、真实 session ID 前缀、私有 artifact 链接、一个 `100.64.212.0/24`（CGNAT 段，来自真实会话的行内代码），判断不需要改写历史。报告在 `tmp/2026-10-28-public-scan/`
2. `setup-secrets.sh --sparkle`：新生成 Sparkle 密钥（备份 `~/Sync/apple-developer/sparkle/agent-session-manager_ed25519.key`），配好 8 个 secrets 和 tap deploy key
3. `make release-local`：两次 Accepted，dmg 里的 app `source=Notarized Developer ID`，`syspolicy_check` 通过（`release-local-0.0.0.log`）
4. 打 tag 前的本机 feed 测试（`e2e-setup.sh`，`shots/01–04`）：0.9.0 → 发现 0.9.1 → 下载 → Ready to Install → Install and Relaunch → 同路径变成 0.9.1 (2)，About 显示 0.9.1 (2)，再检查提示 up to date
5. CI run #1（dispatch）：全部成功，冷缓存 15.5 分钟（`ci-run1.log`）
6. 打 `v1.0.0`，run #2 两个 job 成功。`verify-dist.sh 1.0.0`：checksum、appcast 版本 / 长度 / URL、EdDSA 签名、`latest/download/appcast.xml` 与本次一致、bundle 公钥一致、Gatekeeper、`syspolicy_check` 全过
7. brew：`brew fetch`、装到临时目录、`spctl` 显示 Notarized Developer ID、`syspolicy_check` 通过、`brew audit --cask` 无输出；之后 `brew uninstall`
8. 真实 feed：本地 0.9.0 (1) 经菜单「Check for Updates…」发现 1.0.0 → 安装 → 重启，app 变成 1.0.0 (2)，带票据，About 显示 1.0.0 (2)（`real-feed/shots/01–03`）
9. 每次测试后按 PID 结束实例，`state.json` 与备份一致，删除 Sparkle 的偏好、Caches、HTTPStorages，停掉 feed 服务

## 遇到的问题

- **启动时的自动检查没弹提示**（真实 feed 那次）：偏好里有 `SULastCheckTime` 和 alert 窗口位置，屏幕上没有窗口。用本机 feed 复现（`repro-launch-alert.sh`，每秒列窗口 25 秒），读 Sparkle 2.10.0 源码确认：普通 app 不在前台时，定时检查发现的更新要等 app 下次被激活才显示。测试实例从后台 shell 启动，抢不到焦点（`frontmost=false`）。第一次本机测试能弹，推测是那时 app 拿到了焦点。没有去激活 app 实测，结论来自源码
- **Install and Relaunch 点了没反应一次**：「Ready to Install」刚出现就用 System Events 点，进程没退；再点一次就好了
- **cua MCP 中途断开**：后半程的 Sparkle 按钮改用 System Events 的 AX press（只按按钮，不发按键、不动剪贴板）
- Sparkle 重启后的进程不带启动时的环境变量，测试实例重启后用了真实索引（只读加增量扫描，`state.json` 未被改）
