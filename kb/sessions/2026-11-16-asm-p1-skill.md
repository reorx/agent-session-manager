## 踩过的坑

- 第一次跑 core 测试有 1 个失败（`tests/usage.rs` 的 `a_session_is_active_for_a_model_when_it_called_that_model_in_the_span`），同时报 `usage.rs:238` 的 `model` 未使用，而工作区里那一行明明用到了它。原因：调试版 `libagent_session_core` 是 00:25 由别的源码树编出来的（`tmp/2026-11-12-usage-stats/*/source*`、`usage-p2-accept2/repo` 都是旧版本的导出树）。cargo 按工作区内的相对路径算包的哈希，几棵树共用 `~/Library/Caches/cargo-target` 时产物互相覆盖；主 checkout 的源文件 mtime 比产物旧，cargo 就当它是新的，直接拿来链接，连旧的警告也照样重放。`touch crates/core/src/usage.rs`（只改 mtime）后重编，全部通过。release 版和装好的 `asm` 是我 00:32 那次在主 checkout 里编的，不受影响（当时有编译）。

## 交给协调者

1. **导出的源码树会污染共用构建目录**（见「踩过的坑」）。后果：主 checkout 的测试可能跑在别的源码上；`make install-cli` 在导出树编过 release 之后运行，可能把别的源码编出的 `asm` 复制到 `~/.local/bin`（决定 26 想避免的正是这种情况）。建议：导出树里的 cargo 一律用自己的 `CARGO_TARGET_DIR`（P1-7 计划在导出树里验收、cache-break 的 agent 也会编），写进 brief 和 AGENTS.md「开发命令」；已有的导出树用完可删。
2. AGENTS.md（归协调者）：「开发命令」加 `make install-cli`（副本，更新后重跑；默认用 `index-cli.sqlite`）；「结构」或 Documentation 加 `skills/asm/`（SKILL.md、`references/cli.md` 规范、`finding-sessions.md`）和 `.claude/skills/asm` 链接；README 有一节 CLI，改命令时要同步。
3. 计划 `session-search.md` Tech Design「脚本与构建」写的是 `ln -sf`、「skill」写的前提检查是 `command -v asm` / `asm --version`，按决定 26 和 P1-1 R1 #6 改为复制和 `asm projects --help`；第 10 步可勾选，第 12 步里 README / product-prd 已在本提交完成。
4. 要用户确认：`finding-sessions.md` 的例子用了用户真实会话的片段（项目名 vibench、cw_edge、设备名 Genji / Maiev、几句工作内容），仓库是公开的。已删掉 IP、内部域名和一个地名。要换成虚构内容的话改例子即可，命令序列不变。
5. 代码问题（不改，供定夺）：CLI 等账本锁用的是 `Ledger` 连接自己的 5 s busy timeout，而不是 CLI 的 2 s，app 扫描时 `asm` 最多多等 3 s 才回退。若要和「2 秒」一致，可在 CLI 打开索引后把账本连接的 busy timeout 也设成 2 s。
6. 范围外：`Makefile` 的 `.PHONY` 漏了 `screenshot-resident`、`test-screenshot-resident`（usage-stats 期间加的目标），没改。scratch 的 `index/`（约 230 MB，含账本）在 P1-7 用完后可删；`sandbox-home/` 可删。
