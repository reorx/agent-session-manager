# 用量统计第 1 期 app：状态栏的 Today、4:00 分日、自动扫描

## 协调者摘要（usage-p1-app）

- 结果：完成 usage-ledger 步骤 2、8、9 和步骤 10 的自动化部分；没有改 core，没有跑 GUI 实机验收（决定 7），只用 fixture 副本自查了验收脚本。
- 提交：代码、测试、脚本、文档、spec 写回与本总结在同一个提交；hash 见交付回复，或 `git log -1 --format=%H -- kb/sessions/2026-11-16-usage-p1-app.md`。
- 测试：`cargo test -p agent-session-manager` 162 通过 / 0 失败 / 2 忽略；`make test` 527 / 0 / 7。新用例 14 个（model 4、store 3、keyboard 7），其中 4 个 keyboard 用例做过变异检查：去掉对应实现就失败。
- parity：活数据 17 / 4（失败全是比对期间别的 session 在写入：更新时间差一分钟、扫描数多 1）；在 core 任务的固定快照上 21 / 0。
- 自查：fixture 副本上跑通 `make screenshot-usage`，搬走带今天调用的 S1 后，扫描、重建后 Today 都是 $0.09（`tmp/2026-11-12-usage-stats/usage-p1-app/selfcheck2/`）。
- 决定：`ScanDone` 加 `quiet`；删掉 `RangePreset::bounds`，统一用 `AppRoot::usage_day`；扫描刷新不滚动的做法与 spec 设想不同（照常选中，只撤掉滚动请求），范围含手动扫描。都写回了 spec。
- 风险第二条（自动扫描后表格滚回选中行）：无界面测试复现（滚动位置 −86px → 0），已修并成用例。
- 未验证：真实窗口里的激活扫描、10 分钟定时、滚动手感；真实数据。见「给验收的做法」。
- 交给协调者：AGENTS.md 的新环境变量与命令、两条 core 观察，见文末。

## 实现概要

- `model.rs`：`RangePreset::bounds_on` 的每个边界都是 `day_start_ms(day, &Local)`（4:00）；删掉 `bounds` 和 `local_midnight`；新增 `today_at(now_ms)`。
- `store.rs`：`StoreRequest::Scan { quiet }`；事件 `Usage { sessions, full }`、`UsageUnavailable`、`ScanSkipped`，`ScanDone` 多了 `quiet`。启动时 `load()` 之后 `load_usage()`（读账本出错时发 `UsageUnavailable` + `Failed`，扫描照常）；`scan` 收集 `ScanEvent::Session` 的 id，成功后在 `ScanDone` 前发这些 session 的账本行（没有就不发）。请求处理抽成 `Worker::serve`：安静的扫描遇到 `is_busy` 发 `ScanSkipped`。
- `main.rs`：字段 `usage`、`usage_available: Option<bool>`、`usage_day`、`today`、`today_label`、`scan_in_flight`（初值 true）、`last_scan_done`（executor 时钟）、`scans_done`、`_auto_scan`。`auto_scan(trigger)`（30 秒节流）、`scan_ended`、`roll_day(now)` → `refresh_today(now)`（上界下一个 UTC 整点）、`status_left`。窗口激活和 600 秒循环任务都走 `roll_day` + `auto_scan`。扫描引起的刷新走 `relocate_selection(false)`。
- `toolbar.rs`：`set_range` 和 `date_presets` 用 `self.usage_day`。
- 脚本：`ASM_USAGE_AUTOPLAY=<gate 目录>`、`scripts/screenshot-usage.sh`、`make screenshot-usage`。

## 给验收的做法

不发按键、不点击；步骤由文件驱动，截图按窗口 ID。

1. **准备数据副本**（决定 9：不打开真实索引和账本）。在 `tmp/2026-11-12-usage-stats/accept/` 下：
   - 小份真实数据：把 `~/.claude/projects/` 里几个项目目录和 `history.jsonl` 复制到 `accept/claude/`（真实记录里有今天的调用，Today 自然非零）；或
   - fixture：`cp -R crates/core/tests/fixtures/claude accept/claude`，再用 `python3 tmp/2026-11-12-usage-stats/usage-p1-app/append-response.py accept/claude/projects/-Users-me-Code-alpha/11111111-aaaa-4bbb-8ccc-000000000001.jsonl` 加一条现在时间的调用（opus-5 下是 $0.09）。
2. **跑脚本**（从仓库根目录，`A` 用绝对路径）：

   ```sh
   A=$PWD/tmp/2026-11-12-usage-stats/accept
   mkdir -p "$A/removed"
   ASM_DB=$A/index.sqlite ASM_CLAUDE_DIR=$A/claude \
   USAGE_BEFORE_SCAN="mv <要删的记录文件和它们的 subagent 目录> '$A/removed/'" \
   USAGE_HOLD=700 make screenshot-usage SHOT_DIR=$A/screenshots
   ```

   `ASM_STATE` 不用设（默认在输出目录新建）。不设 `ASM_DB` 或 `ASM_CLAUDE_DIR`、或指向真实位置时脚本拒绝运行。
3. **看什么**：
   - 日志标记 `autoplay-usage: ready · Today $X`、`scanned · …`、`rebuilt · …`，三个 X 应相同（验收第 2 条）；截图 `1-ready.png`、`2-scanned.png`、`3-rebuilt.png` 的状态栏左侧末尾是同一个 `Today $X`。
   - 账本核对：`sqlite3 "file:$A/usage-ledger.sqlite?mode=ro" "SELECT model, fast, long_prompt, sum(responses), sum(input), sum(cache_write_5m), sum(cache_write_1h), sum(cache_read), sum(output) FROM usage_hourly WHERE hour >= <今天 4:00 的 unix 秒>/3600 GROUP BY 1,2,3"`，按 `crates/core/src/pricing.rs` 的单价算出的合计应等于 X；删文件前后、重建后 `SELECT count(*) FROM responses` 不变。
   - 日志里的其他行：`today: Today $X (since <日期> 4:00, N calls)`（Today 变化时）、`auto-scan: timer` / `auto-scan: window activated`、`scan (automatic): …`、`scan skipped: …`、`usage day: a → b`。
4. **10 分钟不动**（验收第 13 条）：`USAGE_HOLD=700` 让 app 在重建后再开约 11 分钟，结束时截 `4-held.png`。期间在另一个 shell 用 `append-response.py` 往副本里一个还在的记录文件追加一条。定时器从 app 启动时算，每 600 秒一次，日志出现 `auto-scan: timer`，随后 `today:` 变化，`4-held.png` 里那一行排到最前、Updated 是追加的时刻。
5. **窗口激活**：把窗口切到前台（距上次扫描超过 30 秒）会打 `auto-scan: window activated`。脚本不会切前台；要验就手动点一下窗口，或者只看定时器那条，激活路径已有无界面用例。
6. **风险第二条（自动扫描后表格不滚回选中行）**：无界面测试已复现并覆盖（`an_automatic_scan_does_not_scroll_the_table_back_to_the_selected_row`）。真实窗口里要验得手动滚动表格，这个 autoplay 不做；做不了就记「未验证（有自动化用例）」。
7. 截图偶尔失败（`could not create image from window`，自查时第一次遇到，原样重跑就过了）：换一份新的副本重跑，因为副本里的记录文件已被挪走。

## 交给协调者

- **AGENTS.md**：
  - 结构：store 线程在第一次 `Loaded` 之后发账本的全部用量，之后每次扫描只发写过的 session；`AppRoot` 在主线程算今天的费用（`roll_day` / `refresh_today`），应用开着时自己做安静的增量扫描（窗口激活、每 10 分钟，30 秒节流）。
  - 环境变量：`ASM_USAGE_AUTOPLAY=<gate 目录>`（文件驱动的扫描 / 重建，见 gpui-kit-guide）。
  - 开发命令：`make screenshot-usage`，必须设 `ASM_DB`、`ASM_CLAUDE_DIR` 指向副本。
  - GPUI 规则可考虑加一条：扫描引起的刷新不把表格滚回选中的行（`relocate_selection(false)`），新加的刷新入口照这个走。
- **core 观察（不阻塞，未改）**：
  - `Ledger::usage(Some(ids))` 读出整张 `usage_hourly` 再在 Rust 里按 id 过滤：现在 5,510 行无所谓，一年后约 5 万行时每次扫描多读一遍。可以改成 `WHERE session_id IN (…)`。
  - 账本连接的错误被转成不带 `rusqlite::Error` 的 anyhow 错误（为了不被当成索引损坏），所以 `is_busy` 认不出账本被锁：安静的扫描碰上账本被另一个进程锁满 5 秒时，会报 `Failed` 而不是 `ScanSkipped`。账本的锁只在写入那一下，很难碰上。
- **known-issues**：没有新增。「重建索引后已删 session 的用量丢失」那条按 brief 由协调者在 P1 签收后处理。
- **范围外**：日期选择器显示的默认区间（没选过 Custom 时是「本月到今天」）只在启动时设一次，跨过月初换日后不会自己更新；影响很小，没改。
- 工作区里没有出现别人的未提交文件。

## 踩过的坑

- 新写的 keyboard 用例第一次跑就全绿，不能说明它们在测东西：做了四处变异，确认去掉实现后各自失败。
- fixture 的 S1 在 history.jsonl 里：删掉记录文件再重建，它会作为 History 行回到索引，`ScanEvent::Session` 带上它的 id，账本行也跟着重发（内容不变）。验证「界面保留重建读不到的用量」要用不在 history 里的 S2。
- `set_selected_row` 的滚动是写进 `UniformListScrollHandle` 的延迟请求，所以能在同一个 update 里撤回；直接置空会顺带丢掉别处刚发的滚动请求，要 take 出来再放回。
- 测试窗口创建时不是激活的，`observe_window_activation` 不会自己触发；`window.activate_window()` 才会。
- 节流计时如果用 `Instant::now()`，测试里只能真等 30 秒；用 `background_executor().now()` 能跟着 `advance_clock` 走。
- `make parity` 在有别的 agent 写 session 时几乎必然有几组失败；要「通过」得用固定快照。
- 自查时一次截图报 `could not create image from window`，重跑即过，原因没查到。
