## 实现

CLI（`crates/core/src/bin/asm/`）：

- `agent.rs`：三个新命令共用的部分。`RangeArgs`（`-d` 与 `--since` / `--until` 由 clap 互斥，`--since` 晚于 `--until`、负的 `--days` 报 `UsageError`）、`Range`（标签、`[since, until)`、`json()`）、`excluded_session`（`CLAUDE_CODE_SESSION_ID` 非空且没有 `--include-self`）、标题 / 项目名 / 恢复命令及其原因、RFC 3339 时间、`«»` 标记、`LookupError`（`NotFound` / `Ambiguous`）和 `App::fail_as_json`。
- `search.rs`：`Query::parse` 和 `KindSet::parse` 的错误直接作为 exit 2 的消息；默认范围看 `Engine::for_query`（index 不限时间，scan 30 天）；`regex_fallback()` 逐条写 stderr；`select_sessions` → `search(…, SearchOptions { snippets, sort, limit })`；结果头的回合数用 `SessionHits.turns`，`meta.total` / `shown` 用 `SearchOutcome.total` 和结果数，`meta.scan` 是 `SearchOutcome.scan`。
- `session.rs`：`find_by_prefix`，0 个 `NotFound`、多个按更新时间降序 `Ambiguous`；`turns` 用 core 的 `turn_count`（`kind = 'prompt'` 的行），`prompts` 用 `user_msg_count`；窗口用 `ModelCatalog::load` + `context_window`，和 app 一样。
- `projects.rs`：`select_sessions`（只带时间范围和排除）后按 `project_key` 分组计数、取最大 `updated_at`，按最近活动降序、同时间按路径排。
- `main.rs`：三个子命令；`refresh` / `open_db_refreshed` 返回 `Refresh`（`done` / `busy` / `skipped`）给 `meta.index_refresh`，旧命令仍用 `open_db`，行为不变；`UsageError` → exit 2。新方法叫 `find_sessions` / `session_card` / `list_projects`，因为 `old.rs` 里已有私有的 `session` / `search_index`，不想动 `old.rs`。

core `session.rs`：`resume_command`、`shell_quote`（原样从 app 搬来）、`SessionKind::of`、`files_touched`。app 的 `actions.rs` 用 `pub use` 重新导出 `resume_command`（测试照旧调用），`model.rs` 的 `Kind::of` 和 `files_touched` 改为调 core。

恢复命令的原因（与 app `actions::available` 同序）：history only → 只剩收藏副本（收藏且原文件不在）→ ID 不是纯字母数字和 `-`（`none (no plain session id)`）。`cd` 的目录是 `project_path`，没有时用 `cwd`，存在且是绝对路径才带 `cd`。

## 规范改动（`skills/asm/references/cli.md`）

- R1-4：`projects` 的 JSON 改为 `project_path`、`project`、`project_key`、`sessions`、`updated_at`；「同一样东西同一个键」的列表补上 `project`、`updated_at`。
- R1-5：TERMs 一节加一条：`search` 用 `--` 隔开以 `-` 开头的 TERM（选项都写在 `--` 前），`transcript --grep` 用 `--grep=-rf`。`search` 的部分有测试；`transcript` 的部分归 P1-5。
- `meta.scan`（scan 引擎读了多少文件 / 字节、整份跳过多少，index 为 `null`），加进示例和字段表。
- `meta.excluded_session`：只要排除生效（设了变量、没有 `--include-self`）就填，不论它本来会不会命中。原文「when it was left out」有两种读法。
- 空结果提示：一条都不适用时（全时段、全类别、单个 TERM、无过滤）给 `other ways of saying each TERM`，不留一个空的 `try:`。
- 第一行：多个 `--project` 用 `,` 连接；标题和首条 prompt 都没有时 `title: (no prompt)`（JSON 为 `null`）；片段没有时间时省略时间；JSON 的 `title` 和文字一样截到 120 字符；`project` 在没有 `project_path` 时回退到 `cwd`、再到编码目录名。
- `session`：`turns` 一行的说明改了：括号里的 prompt 数按脚本口径数，可以比回合数多也可以少（脚本口径数通知和 compact 摘要、不数只贴图没有文字的 prompt；fixture S1 是 4 回合、3 prompts，差的是第 3 回合那条只有图片的）；歧义时超过 20 个加一行 `… N more`，`--json` 时 stderr 只有首行；`none (no plain session id)`。
- 时间范围：`--days` 要 ≥ 0；标签 `last 1 day`、`last 0.5 days`。
