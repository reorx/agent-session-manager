# P3 搜索优化：可插拔的文本索引（分词全文、可选的向量检索）

总 plan 见 [index.md](index.md)；依赖 [session-search.md](session-search.md) 的会话级搜索接口。

## PRD

### 背景

P1 之后，找会话用的是按字面匹配：全文索引按三个字符切词，工具输入输出靠扫描原始文件。它能解决大部分问题，但有三类会漏：

- 说法不同、意思相同（「连不上网」和「网络请求一直超时」），只能靠 agent 自己想全同义词；
- 没有相关度，结果只能按时间或命中次数排，常见词一多，真正相关的会话被埋在后面；
- 工具输出体量是对话文本的 10 倍以上，按字面扫描在长时间范围上慢。

近两年有不少同时支持中文分词全文检索和向量检索的现成组件，有的嵌在应用里，有的是独立运行的单个程序。

### 目标

在不改变 `asm search` 用法和输出的前提下，可以选择接入一个更好的文本索引：中文分词的全文检索带相关度排序，可选的语义（向量）检索，以及两者混合。默认仍是现在的内置索引，不装任何东西也能用。

### 功能与交互

- 会话里的文字（按文本类别、带会话和回合）以统一的方式送进所选的索引，随记录文件的增长增量更新；换索引、重建索引都不影响内置索引。
- `asm search` 加一个参数选择检索方式（内置 / 分词全文 / 向量 / 混合）；输出格式不变，只多一项相关度，排序可以按相关度。
- 用户可以看到每个可选索引的状态：是否已安装、覆盖了多少会话、最后更新时间、占用空间。
- 选用独立运行的组件时，它没在运行要有清楚的提示，并回退到内置索引。
- skill 的找会话方法说明什么时候该用哪种检索方式。

### 不做的事

- 不默认开启任何需要下载模型或安装组件的检索方式。
- 不把会话内容发到本机以外（embedding 只用本地模型）。
- app 界面接入不在这一期（另开 plan）。

### 验收标准

- 待开工时，在选型调研完成后补充：至少包括「一组本机真实查询上，相对 P1 的召回改善」「增量更新的耗时」「索引占用空间」三项有数字的标准。
